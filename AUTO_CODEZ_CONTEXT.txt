AUTO CODEZ — DOCUMENTO DE CONTEXTO PERMANENTE

============================================================
1. PRODUTO
============================================================

Auto CodeZ é um aplicativo desktop real em Electron + Vite + TypeScript. É uma plataforma de desenvolvimento assistida por múltiplos provedores de IA, com interface própria, agente, execução controlada de ferramentas, projetos locais, chats, configurações, plugins futuros e conta/sincronização.

Arquitetura antiga baseada em automação de navegador/UI Automation para ChatGPT, Claude e Gemini não é mais o núcleo.

Fluxo principal:
Auto CodeZ -> AI Runtime -> Provider Adapter -> API -> modelo.

Tratar como software de produção: mudanças incrementais, código limpo, validação real, sem refatorações amplas sem necessidade.

5. ESTADO DE API KEYS E ERROS
============================================================

Fluxo:
provider -> nome -> API Key -> modelo/base URL opcional -> validação -> model discovery -> salvar.

API Keys são secrets. Localmente usar safeStorage. Nunca salvar plaintext em providers.json.

Erros devem distinguir:
authentication, billing, quota, rate limit, network, server, invalid request e unknown.

Estado observado em 01/09/2026:
- Google AI respondeu corretamente a um primeiro “olá”.
- Depois, criação de pasta retornou falta de créditos/cota.
- OpenAI e Anthropic também estavam sem créditos no momento.
- Isso prova que o fluxo alcança os providers.
- Prioridade é classificação e apresentação correta de billing/quota, não erro genérico.

14. CONTA AUTO CODEZ
============================================================

Conta não é login cosmético. É infraestrutura central do produto.

Objetivo: instalar Auto CodeZ em outro PC e recuperar o ambiente do usuário sem depender de backup manual perdido.

Dados sincronizáveis incluem:
- API Keys/secrets de forma segura;
- chats e histórico;
- configurações e preferências;
- biblioteca;
- projetos marcados para sincronização;
- backups;
- integrações;
- permissões externas;
- dispositivos conectados;
- demais dados persistentes do produto.

Não existe dispositivo rei. Vários dispositivos têm acesso equivalente aos dados sincronizados.

Recursos físicos continuam locais: filesystem, processos, terminal, hardware, aplicativos instalados e pastas explicitamente não sincronizadas.

Um dispositivo remoto não ganha automaticamente controle físico de outro computador.

16. LOCAL-FIRST / OFFLINE
============================================================

Decisão arquitetural permanente:
AUTO CODEZ = LOCAL-FIRST + CLOUD SYNC + OFFLINE QUEUE.

Se internet cair:
- sessão não é perdida;
- chats/histórico/contexto local continuam disponíveis;
- projetos locais continuam disponíveis;
- configurações continuam disponíveis;
- alterações continuam salvas localmente;
- operações dependentes da cloud ficam pendentes;
- UI permanece utilizável.

Quando internet voltar:
- fila é processada;
- servidor confirma;
- estado vira sincronizado;
- conflitos são apresentados quando necessário.

Regra: nunca apagar alteração local porque sync falhou.

Fluxo:
alteração local -> salvar localmente -> fila -> tentar sync -> confirmação -> sincronizado.
Falha -> salvo localmente + pending.
